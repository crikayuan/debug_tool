## 3. 失败项详情与归因

本次**未发现需要工程师返工的源码 Bug**。两处异常均经复测归因为「非源码缺陷」。

### 3.1 边缘套件 H —— QoS0 突发丢包（**非缺陷，测试期望修正**）

- 现象：QoS0 快速发布 50 条（间隔 0.02s），后端仅收到 20 条。
- 根因定位（对比实验）：

  | 场景 | 送达 |
  |---|---|
  | QoS1 @0.02s × 20 | **20/20** |
  | QoS0 @0.02s × 20 | 10/20 |
  | QoS0 @0.05s × 20 | 20/20 |
  | QoS1 @0.02s × 50 | **50/50** |

- 结论：**QoS0 为“至多一次”best-effort，公共 Broker（EMQX）在突发下会丢弃**；同速率 QoS1 因有 PUBACK/重传而 100% 送达，证明**后端处理能力足够**，非后端瓶颈。
- 关键：后端 `stats.receive_count` 与订阅 `count` 均等于**实际到达数**（无虚计/漏计），统计准确。
- 处理：已修正我的测试——「无丢包」断言改用 QoS1；QoS0 仅作 best-effort 观测并单独校验「count == 实际到达」，通过。
- 归因：**环境/Broker QoS 语义**（非源码 Bug，非测试代码 Bug）。

### 3.2 边缘套件 J —— 两实例“B 未收报”（**非缺陷，公共 Broker/编排抖动**）

- 现象：边缘套件末尾两实例用例中，B 后端 `count=0`（A=3），且发布端 `rc=0`（确已发出）。
- 复测：
  - 专项隔离用例 `mqtt_multi_test.py`：连跑 **3 次**，均 A=3 / B=3，ClientID 唯一、双方在线。
  - **复现边缘上下文**（A 先突发 50 条 + A 重连，再接入 B，双方订阅同一主题）：A=3/3、B=3/3。
- 结论：在隔离/半压环境下**稳定通过**，边缘套件中的偶发 0 属于公共 Broker 抖动或长链路编排时序抖动。
- 归因：**环境/网络抖动**（按路由规则重试确认后标注，不算缺陷）。AC-11 以隔离用例为准 → **通过**。
