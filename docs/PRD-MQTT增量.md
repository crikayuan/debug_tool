> 产品：调试助手（Debug Assistant）· 桌面端网络/串口调试工具
> 版本：v1.0.0 → v1.1.0（本次增量）
> 文档类型：**增量 PRD**（仅描述本次变更，不重述产品全貌）
> 撰写：产品经理 许清楚
> 日期：2026-10-14
> 依据：`docs/MQTT功能实施计划书.md`、`docs/ui_preview_v3.html`（已评审定稿）、现有源码 `netassist/front/src/views/DebugView.vue`

## 1. 变更概述

**本次增量在现有「网络调试 / 串口调试」两大模式之外，新增独立第三模式「MQTT调试」，实现 MQTT 报文的连接、订阅、接收与发布（一期仅核心收发）。**

现有网络的 TCP / UDP 与串口调试功能不做任何改动。

---

## 2. 产品目标

针对码头 / 泊位等现场设备调试场景，工程师需要经 MQTT Broker 中转，观察设备上报报文并下发控制指令。本次增量达成三个目标：

1. **打通 MQTT 收发链路** — 让工程师无需第三方工具（MQTTX / mosquitto_pub 等），在调试助手内即可连接公共或自建 Broker，完成订阅、接收与发布。
2. **参数区不被污染** — 以独立第三模式承载 MQTT 的专属参数（Broker / ClientID / 会话 / 心跳等）与交互模型（发布 / 订阅），保持网络与串口两个模式左栏干净，避免历史上出现过的「界面杂乱」问题。
3. **面向现场可靠性** — 支持多开实例互不踢线、断线自动重连并恢复订阅、订阅持久化，贴合现场反复连通、跨天作业的真实用法。

## 5. UI 设计说明

依据已定稿的三模式 UI 统一稿（`ui_preview_v3.html`），MQTT 模式复用现有三栏骨架与统一按钮规范（主操作蓝底 / 危险操作红底仅用于「断开连接」/ 状态提示橙描边仅用于「暂停显示」/ 行内操作用纯文字链接）。分三块描述：

### 5.1 顶部模式切换

- 位置：标题栏左侧「调试助手」标题右侧。
- 形态：分段互斥控件，三个选项 `网络调试` / `串口调试` / `MQTT调试`。
- 行为：选中 `MQTT调试` 时，左栏「连接参数」区、中栏内容区、发送区「发布主题」行同步切换为 MQTT 版；右栏「订阅」Tab 由隐藏变为可见。
- 切换离开 MQTT 模式时（若有连接）自动断开，右栏若停留在「订阅」则切回「快捷指令」。

### 5.2 左栏 —— 连接设置（MQTT 参数区）

标题「连接设置」，下设折叠分区，MQTT 专属字段位于「连接参数」分区：

| 控件 | 形式 | 默认值 / 说明 |
|---|---|---|
| Broker | 文本输入 | `broker.emqx.io`（公共测试 Broker，允许填写自建地址） |
| 端口 | 数字输入 | `1883` |
| ClientID | 文本输入 | 默认自动生成的 `debug-assistant-<8位随机>`，可覆盖 |
| 用户名 | 文本输入 | 可选，空则不带 |
| 密码 | 密码输入 | 可选 |
| 会话 | 两个复选：`Clean`、`自动重连` | 默认均勾选 |
| 心跳 | 数字输入 | `60`（秒） |

- 分区底部一行灰色提示：「默认 MQTT 3.1.1；TLS / 遗嘱 / 5.0 / WebSocket 二期支持」。
- 已连接时上述输入控件置灰不可编辑。
- 其余分区（显示设置、发送设置、数据保存）沿用现有控件与默认值，不做新增字段。
- 底部固定区：「接收 / 发送」统计 + 「计数清零」+ 主按钮「打开连接 / 断开连接」（与其余两模式完全一致）。

### 5.3 中栏 —— 消息视图与发送区

- **工具栏**：标题由「数据日志」切换为「**消息记录**」；右侧保留「HEX / 文本」「编码」「保存」「清空」。MQTT 消息在列表内以「消息卡片」呈现（非逐行日志）。
- **连接信息条**（MQTT 模式下常驻工具栏下方）：连接状态点 + `Broker: <host:port>` + `ClientID: <...>` + `订阅: <N> 个主题`；右侧「断开连接」按钮。
- **消息卡片字段**：时间、主题标签（主题名 + 主题色圆点，胶囊底色为主题色 10% 透明度）、`QoS` 徽标、`Retain` 徽标（仅当 retain 为真）、方向（`← 接收` / `→ 发送` / `自动`）、payload 区。
- **发送区**（结构与其他两模式一致）：
  - 顶部新增「**发布主题**」行：`发布主题` 文本输入（占位示例 `berth/cmd/001`）+ QoS 下拉（`QoS 0/1/2`）+ `Retain` 勾选。
  - 下方沿用「文本 / HEX」分段、「结束符」「校验」下拉。
  - 操作区沿用「暂停显示」「发送」「清空」三按钮。

### 5.4 右栏 —— 订阅管理

- 新增第 8 个模块「**订阅**」Tab，**仅 MQTT 模式可见**；MQTT 模式下进入时默认选中该 Tab。
- 面板标题「**订阅管理**」，包含：
  - 新增订阅行：主题输入（占位提示「主题，支持 + / # 通配符」）+ QoS 下拉（`QoS0/1/2`）+ 主按钮「订阅」。
  - 订阅卡片列表：左侧主题色条 + 主题名 + 元信息（`QoS n`、`n 条消息`）+ 行内文字操作「设为默认」「取消」。
  - 列表为空时显示空状态提示。
  - 面板底部灰色提示：「点击订阅卡片可把主题填入发送区；断线重连后自动恢复订阅」。

### 5.5 明确「不改动」的部分

- 网络调试模式（TCP Client / TCP Server / UDP）的**全部**现有功能与交互。
- 串口调试模式的**全部**现有功能与交互。
- 标题栏右侧「已连接」状态标签、隐藏参数 / 隐藏模块按钮、右栏可拖动分隔条与自适应折叠逻辑。
- 现有 7 个右栏模块（快捷指令 / 批量发送 / 历史发送 / 自动应答 / Modbus / 工具箱 / 设置）的内部实现。
- 全局持久化机制（本机数据文件 + localStorage 兜底）与日志保存能力仅做「新增 key」级别的扩展，不改动既有字段。

## 6. 关键交互规则

1. **消息卡片按 Topic 着色**：进入会话的主题按首次出现顺序依次分配调色板颜色（8 色循环），同一主题在消息卡片标签、色条、订阅卡片色条上颜色一致，便于多主题并发时快速区分。
2. **点击订阅卡片填入发送主题**：点击订阅卡片主体（非行内按钮），将该订阅主题写入发送区「发布主题」；点卡片内「设为默认」则将其设为默认主题并同步填入。
3. **断线重连自动恢复订阅**：本地维护订阅表；连接建立成功（含自动重连）后无条件重放订阅表，恢复原订阅关系。
4. **多开 ClientID 唯一化**：每次新建连接默认自动生成唯一 ClientID；提供「重连时在 ClientID 追加时间戳」的开关以规避极端冲突；若 Broker 返回 `Identifier rejected` 类错误，前端给出明确提示（如「ClientID 被占用，请更换」）。
5. **发送前置校验**：点「发送」时若「发布主题」为空，阻止发送并提示「请先填写发布主题」。
6. **暂停显示语义与现有一致**：暂停期间消息仅计数不渲染入列表，按钮翻转为橙色高亮并显示待显示条数；恢复后合并显示。
7. **协议版本固定**：一期固定 MQTT 3.1.1，不在 UI 暴露版本切换控件。
