## 一、结论摘要

「网络扫描」定位为**第四个顶级模式**（与网络调试 / 串口调试 / MQTT调试 并列），而不是塞进右栏模块 —— 原因是扫描结果是一张 8 列的宽表格，需要中栏横向空间，右栏 300px 装不下。

技术实现上**不需要新增任何第三方依赖**，全部用 Python 标准库 + ctypes 完成（`socket` / `concurrent.futures` / `ipaddress` / `ctypes`），因此对打包体积和 PyInstaller 收集零风险。默认探测方式为 **ARP 表 + TCP 连接探测**，**不需要管理员权限**。

参考了 Angry IP Scanner、Advanced IP Scanner、Free IP Scanner、SoftPerfect Network Scanner 以及国内「局域网设备扫描工具」，取其中与现场调试相关的核心能力，砍掉远程关机 / WMI / SNMP 等企业运维重型功能。

### 3.1 布局

网络扫描模式**只用两栏**（左栏设置 + 中栏结果），**不显示右栏**。理由：右栏的 8 个模块（快捷指令 / 批量发送 / 自动应答 / Modbus 等）都是"发数据"用的，在扫描场景下无用；且结果表格需要横向空间。

### 3.2 交互要点

| 交互 | 行为 |
|---|---|
| 点「开始扫描」 | 左侧按钮禁用、「停止」启用、顶部状态标签变「扫描中」（蓝），进度条实时推进，结果逐行插入表格 |

| 双击结果行 | 选中并提示可跳转 TCP 连接 |
| 点结果行最左 **★** 或底部「收藏」 | 切换收藏状态，**收藏的设备自动置顶**（在收藏组内仍按 IP 排序），持久化 |

| 筛选框 | 实时按键字过滤 IP / MAC / 厂商 / 主机名 |

完全沿用已定稿的三模式统一体系：主色 `#2f6fed`、在线状态用绿色圆点、离线灰色、端口标签用浅蓝底胶囊、备注文字用暖橙色。按钮只用 `.btn` 一套（primary / danger / default / ghost / sm 尺寸），分段控件用 `.seg`。

## 四、技术方案

### 4.1 探测策略（核心设计）

三种方式组合，按可靠性排序：

| 方式 | 原理 | 是否需要管理员 | 速度 | 能拿到什么 |
|---|---|---|---|---|
| **ARP 表** | ctypes 读 `GetIpNetTable`（系统 ARP 缓存） | 否 | 极快（一次调用拿全部） | IP + MAC |
| **TCP 探测** | connect 到目标常用端口 | 否 | 快（并发） | 存活判定、开放端口 |
| ICMP Ping | 子进程 `ping -n 1 -w <ms>` 或 raw socket | 子进程不需要 / raw socket 需要 | 较慢 | 存活判定 |

**默认策略（ARP + TCP）**：

```
1) 先并发 TCP 探测整个网段（唤醒 ARP 缓存，同时判定存活）
2) 扫描结束后一次性读取 ARP 表，把 MAC 补到对应 IP 上
3) 对在线 IP 并发做反向 DNS 解析主机名
4) 用 MAC 的 OUI 前缀查厂商
```

这个组合的好处：不依赖管理员权限、不用发 raw packet、速度快（C 类 254 个地址通常在 3–8 秒内完成）。

**为什么不用 ICMP 作为默认**：Windows 下 raw socket 需要管理员，而 `ping.exe` 子进程每台设备要起一个进程（254 个进程开销大、还会被杀软盯上）。TCP 探测既快又无权限要求。

### 4.4 依赖

**仅新增 1 个第三方包**：

| 包 | 用途 | 体积 |
|---|---|---|
| `mac-vendor-lookup` | OUI → 厂商名，内置 IEEE 完整数据库 | 约 0.3 MB |

其余全部来自 Python 标准库：

- `ipaddress` — CIDR 与范围解析
- `concurrent.futures.ThreadPoolExecutor` — 并发探测
- `socket` — TCP 探测与反向 DNS

## 五、风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 现场交换机禁 ICMP / 设备静默 | 中 | 默认用 TCP 探测而非 ICMP；端口方案含工控常用端口 |
| 2 | ARP 表读取在部分系统版本字段偏移不同 | 中 | 参考本项目已有的 `netif_utils.py` 经验（结构体偏移曾踩坑），先写探测脚本验证再落地 |
| 3 | 并发过高触发网络设备防护 | 中 | 默认 128 并发并允许降到 8；对同一 IP 不重复发包 |
| 4 | 扫描耗时与前端卡顿 | 中 | 结果分批推送、表格虚拟滚动或限流渲染（上限保留最近 1024 行） |
| 5 | 反向 DNS 拖慢整体 | 中 | 主机名解析放在存活判定之后，且带独立超时与并发限制 |
| 6 | 杀软对并发 connect 报警 | 低 | 限制并发；README 提示需放行 |
| 7 | 打包后 ctypes 调用异常 | 低 | 纯 ctypes 无额外 DLL，风险低；打包后实测一遍 |
